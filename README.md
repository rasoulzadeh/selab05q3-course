# 💻 آزمایشگاه مهندسی نرم‌افزار (Software Engineering Lab)

به ریپازیتوری رسمی درس **آزمایشگاه مهندسی نرم‌افزار** خوش آمدید!  
این ریپازیتوری شامل اسلایدهای آموزشی، پروژه‌های نمونه، برنامه‌های هر جلسه و تمرین‌های عملی درس است. هدف این درس، تبدیل دانش تئوری به **مهارت‌های عملی، معماری نرم‌افزار، کدنویسی تمیز (Clean Code) و کار تیمی صنعتی** است.

---

## 🛠️ پیش‌نیازها و ابزارهای لازم (پیش از جلسه اول)

همراه داشتن **لپ‌تاپ در تمام جلسات الزامی است**. لطفاً پیش از حضور در جلسه اول، ابزارهای زیر را روی سیستم خود نصب و آماده کنید:

1. **محیط توسعه (IDE / Editor):**
   * **گزینه پیشنهاد اصلی:** [Visual Studio 2022 - 2026](https://visualstudio.microsoft.com/) با ورک‌لود `.NET desktop development` یا `.NET Web Development` (برای سیستم‌های متوسط و قوی).
   * **گزینه سبک (سیستم‌های ضعیف‌تر یا غیر ویندوزی):** نصب [VS Code](https://code.visualstudio.com/) به همراه آخرین نسخه **.NET SDK (.NET 8 / .NET 10)** و افزونه `C# Dev Kit`.

2. **ابزارهای مدیریت نسخه (Git & GitHub):**
   * برنامه **[Git for Windows](https://git-scm.com/):** جهت اجرای دستورات گیت.
   * برنامه **[GitHub Desktop](https://desktop.github.com/):** محیط گرافیکی و ساده برای مدیریت مخازن گیت (اختیاری اما بسیار مفید).
   * **حساب کاربری فعال در [GitHub](https://github.com/):** جهت ارسال پروژه‌ها و کار تیمی.

---

## 📌 ساختار پروژه‌ها و ارزیابی

در این درس با دو پروژه موازی سروکار داریم:

1. **پروژه داخل کلاس (تمرینی):**
   * سیستم *«مدیریت لوازم و رزرو تجهیزات آزمایشگاه»* که هر جلسه گام‌به‌گام مفاهیم همان روز را روی آن پیاده‌سازی می‌کنیم.

2. **پروژه اصلی تیم‌ها (پروژه منزل):**
   * هر گروه (۲ یا ۳ نفره) باید یک **پروژه اصلی و واقعی** انتخاب کند.
   * تمام مفاهیم تدریس‌شده در کلاس باید هفته‌به‌هفته روی پروژه اصلی پیاده‌سازی و در ریپازیتوری گیتهاب گروه ارسال (Push) شود.

### ⚠️ قوانین مهم ارزیابی و کامیت‌ها (Commit Rules)
* **کامیت‌های منظم و هفتگی:** نمره‌دهی پروژه تماماً بر اساس **تاریخچه کامیت‌ها (Git History)** انجام می‌شود.
* **ارسال یک‌جای کد ممنوع!** اگر کل پروژه شب قبل از تحویل در قالب یک کامیت ارسال شود، **هیچ نمره‌ای به آن تعلق نخواهد گرفت**.
* **کدنویسی تمیز:** رعایت اصول شی‌گرایی، SOLID، تست‌نویسی و ساختار معماری در نمره نهایی مستقیم تاثیرگذار است.

## 📅 سرفصل جلسات آزمایشگاه

* **جلسه ۱:** بوت‌کمپ فشرده C# و آشنایی با مدیریت نسخه محلی (Git)
* **جلسه ۲:** شی‌گرایی، Enumها، اینترفیس‌ها و اتصال پروژه به GitHub (Branch & Push)
* **جلسه ۳:** مهندسی نیازمندی‌ها، تعریف User Story و ساخت Backlog بر روی GitHub Issues
* **جلسه ۴:** مدلسازی سناریوها (Use Case & Sequence Diagrams)
* **جلسه ۵:** معماری نرم‌افزار و تفکیک لایه‌ها (Clean Architecture در .NET)
* **جلسه ۶:** اصول کدنویسی تمیز (Clean Code)، اصول SOLID و الگوهای طراحی (Design Patterns)
* **جلسه ۷:** آنالیز ایستا (Static Code Analysis) و بازبینی کد (Code Review)
* **جلسه ۸:** تست‌نویسی خودکار (Unit Testing) و TDD با xUnit
* **جلسه ۹:** ذخیره‌سازی داده‌ها، لاگ‌گیری و اتوماسیون CI/CD با GitHub Actions
* **جلسه ۱۰:** جمع‌بندی، مستندسازی نهایی (README) و دفاع از پروژه اصلی تیم‌ها
